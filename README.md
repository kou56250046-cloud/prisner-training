# プリズナートレーニング管理アプリ

書籍『プリズナートレーニング』を、進捗管理とフォーム解説を兼ねた個人用アプリにしたもの。
完全ローカル動作・ログイン不要・無料運用。

## 起動

```bash
npm install
npm run dev        # http://localhost:5173
```

## コマンド

| コマンド | 内容 |
|---|---|
| `npm run dev` | 開発サーバー |
| `npm run verify` | 棒人間アニメの幾何を検証（床の突き抜け・接地点のズレ・関節角の異常を検出） |
| `npm run typecheck` | 型チェック |
| `npm run content` | `content/source/` を暗号化して `public/content.enc` を作る |
| `npm run content:extract` | `content.enc` を復号して `content/source/` に戻す（復旧用） |
| `npm run sheets -- <backup.json>` | バックアップJSONを、シートに貼れる TSV に変換 |
| `npm run icons` | PWA アイコンを生成 |
| `npm run build` | 本番ビルド |
| `npm run check:deploy` | 公開サイトが正常に動いているか外から検証 |

## 画面

| URL | 内容 |
|---|---|
| `/#/` | ダッシュボード。連続日数・今日の予定・積み上げ |
| `/#/progress` | 階段ビュー・カレンダー（記録＋予定）・レップス推移 |
| `/#/coach` | 停滞診断・打開策・強化トレーニング・エピソード集 |
| `/#/library` | 種目図鑑。**記録はここから**（ステップ詳細の「記録する」） |

| `/#/anim` | **アニメ作業台**。角度データは暗号化対象外なので合い言葉なしで開ける |

新しい種目のアニメを起こすときは `/#/anim` を使う。

### 記録の流れ

メニューを組む画面は持たない。図鑑でステップを開き、やり方とアニメを見ながら
その場でレップス数とセット数を書いて記録する。セットごとにばらつく日は
「セットごとに入力」に展開できる。記録は1日1セッションにまとめて貯まり、
進捗タブのカレンダーから後で修正できる。

書き忘れた日は、記録シートの日付を「昨日」などに変えれば埋められる。
カレンダーの日付から開く修正シートにも「この日の記録を追加する」があり、
種目とステップを選んでその日付で書ける。過去日ぶんの記録時刻はその日の正午に置くので、
あとから足しても履歴の順序は入れ替わらない。

### スプレッドシート連携

記録は端末の IndexedDB にしかないので、Google スプレッドシートに写しを取れる。
GAS のウェブアプリを1枚立てて、設定 → スプレッドシート連携 に URL と合い言葉を入れる。
記録・修正のたびに全件を送り直すので、直した記録も消した記録もそのまま揃う。
置き方は [`gas/README.md`](./gas/README.md)。

送るのは `記録`（1セット1行）・`日別`・`ステップ別`・`進捗` の4枚と、
復元用の生データを入れた非表示シート1枚。端末を変えたときは「シートから復元」で戻せる。
記録が0件の端末から同期してもシートは消えない（GAS 側で拒否する）。

書き出し済みのバックアップ JSON を、GAS を通さず手でシートに貼りたいときは
`npm run sheets -- record/<ファイル>.json` で貼り付け用の TSV を作れる。
表の組み立てはアプリの同期と同じコードを通るので、中身は一致する。

## 現在の状態

**完成。** ビッグ6 × 10ステップをすべて収録し、記録・進級判定・停滞診断まで動く。

- アニメ: **60 / 60**
- 解説: **60 / 60**
- ルーチン5件・エピソード10件
- テスト68件、アニメの幾何検証60件

ハンドスタンドの STEP1〜3 だけは、書籍が回数ではなく秒数を基準にしているため
`metric: "seconds"` を持つ。UI とコーチングはこの単位を見て表示を切り替える。

## 棒人間アニメーションの仕組み

`src/anim/` に、全60種目で共通のスケルトンリグと再生エンジンがある。

- **絶対角で姿勢を持つ** — 関節角を親からの相対角ではなく「水平から何度」で持つ。
  書籍の写真を見て「体幹は水平から62度」とそのまま書き写せる。
- **接地点は IK でピン留めする** — 壁や床に触れている手足は、関節角ではなく
  「手首のワールド座標」で指定し、逆運動学で関節角を解く。キーフレーム間を
  IK 同士でつなぐと、動作中ずっと接地点がずれない。
- 角度データは `src/content/animations/*.ts`。1種目あたり通常3キーフレーム。

新しい種目を追加する手順:

1. スキャンの写真ページ（解説ページ + 1）を開く
2. スタート/フィニッシュの関節角度を読み取る（本文中の「45度」などの記述で裏取り）
3. `src/content/animations/` にキーフレームを書く
4. `npx tsx scripts/verify-anim.ts` で破綻がないか確認
5. ブラウザで再生して微調整

## 原本の参照方法

スキャン画像はリポジトリに含めない。

- 偶数ページ = 解説（やり方 / 説明 / トレーニング・ゴール / 技術を完璧にするために）
- 奇数ページ = スタートとフィニッシュの写真2枚

**注意: スキャンのファイル番号とページ番号のオフセットは一定ではない。**
プッシュアップ章ではファイル番号 = ページ番号だが、スクワット章では
ファイル番号 = ページ番号 - 1 になっている。写真を開いたら必ずページ下部の
ノンブルで実際のページを確認すること。

| 種目 | STEP1〜10 の解説ページ |
|---|---|
| プッシュアップ | 72, 74, 76, 78, 80, 82, 84, 86, 88, 90 |
| スクワット | 114, 116, 118, 120, 122, 124, 126, 128, 130, 132 |
| プルアップ | 154, 156, 158, 160, 162, 164, 166, 168, 170, 172 |
| レッグレイズ | 188, 190, 192, 194, 196, 198, 200, 202, 204, 206 |
| ブリッジ | 226, 228, 230, 232, 234, 236, 238, 240, 242, 244 |
